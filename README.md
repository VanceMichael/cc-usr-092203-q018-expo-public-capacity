# 东博会公众承载

管理公众开放日的分区容量、排队、可达路线和应急疏散。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块只校验资料边界，不预先实现业务流程。

当前资料反映以下领域事实：

- 公众开放日仅两天，未来空间展区的火箭模型、可上手的AI商品和东帝汶展馆在不同时段形成客流峰值
- 仅按总入场人数限流，仍可能让某条通道或某个互动点瞬间失控
- 互动展项允许观众现场体验，科普展示不计入零售订单
- 预约、现场排队、无障碍通行、团队访客、未成年人陪同和临时封控共同占用局部容量
- 设备故障、展商暂停演示、突发疏散和路线改道会立即改变可达路径

样例另提供六类结构，供承载服务据此计算分区容量、重算可达路线并限定操作范围：

- `zones`：展馆与展区及其容量
- `entrances`：入口及其通向的展区
- `corridors`：展区之间的通道及其容量
- `exhibits`：展项，区分科普展示与零售，标注是否可互动
- `demo_slots`：展项演示时段及其容量
- `staff`：人员能力样例，区域工作人员限定负责展区，指挥席以 `*` 表示跨区

## 本地校验

运行项目自带测试可确认样例资料能够被读取，领域标识、版本、参与方、事实、约束与六类样例均保持完整，且通道、展项、演示时段和人员范围只引用已知的展区与展项。仓库不保存账号、密钥、连接串或真实身份资料。
